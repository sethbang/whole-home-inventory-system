# Security Policy

## Reporting a Vulnerability

The WHIS team takes security vulnerabilities seriously. We appreciate your efforts to responsibly disclose your findings.

### How to Report a Vulnerability

1. **DO NOT** create a public GitHub issue for security vulnerabilities
2. Email security concerns to [security@example.com]
3. Include detailed information about the vulnerability
4. Provide steps to reproduce if possible
5. Include any potential impact assessment

We will acknowledge receipt of your vulnerability report within 48 hours and send a more detailed response within 96 hours indicating the next steps in handling your report.

## Security Model

WHIS is a self-hosted single-tenant household inventory system. Its threat model assumes the deployment is on a trusted LAN or fronted by a reverse proxy/VPN. Anything beyond that requires additional hardening the application itself does not provide (see _Known security limitations_ below).

### Core Security Principles

1. **Data Privacy**
   - All data stored locally on the operator's host
   - No cloud synchronization
   - Backups are plain zip archives (not encrypted at rest — encrypt the host-side volume or the backup destination if that matters for your threat model)

2. **Network Security**
   - HTTPS-only communication in both dev and prod (self-signed CA during development; operator-provided TLS at the reverse-proxy layer in production)
   - CORS defaults restrict origins to `https://` schemes only
   - Local network by default

3. **Authentication**
   - JWT-based authentication via **PyJWT** (HS256 by default — change `ALGORITHM` in settings if you need RS/ES)
   - Password hashing with **bcrypt** via passlib (`bcrypt>=3.2,<4` pinned for passlib 1.7.4 compatibility)
   - Token expiry controlled by `ACCESS_TOKEN_EXPIRE_MINUTES` (default 30)
   - `BYPASS_AUTH` env flag for local development — refuses to load without an explicit `SECRET_KEY` otherwise

4. **Data Protection**
   - SQLite with Alembic-managed schema
   - Image uploads validated by Pillow magic-byte inspection (not trusted `Content-Type`)
   - Upload size cap via `MAX_UPLOAD_BYTES` (default 10 MB) and dimension cap via `MAX_IMAGE_DIMENSION` (default 8000 px)
   - Global exception handler redacts stack traces from HTTP responses unless `DEBUG=true` (dev only)

## Security Features

### Authentication System

- **Password Requirements (current):** WHIS does not currently enforce complexity, minimum length, or common-password checks. Per-route rate limiting via slowapi is enforced on both `/api/token` (login) and `/api/register` — 5 requests/minute/IP each — so the endpoints can't be used for brute-force or account-enumeration probing (see _Network Security_ below).
- **Bypass mode:** `BYPASS_AUTH=true` short-circuits JWT verification and returns the hardcoded `DEV_USER`. The settings module refuses to load with `BYPASS_AUTH=false` and a missing/placeholder `SECRET_KEY`, so there's no default that leaks real auth off.

### Data Storage

- **Database:** SQLite at `settings.DATABASE_URL` (defaults to `backend/database/whis.db`); Postgres is opt-in via `DATABASE_URL=postgresql+psycopg://...`. Alembic is the sole source of truth for schema (the pre-2.0.0 `Base.metadata.create_all()` path was removed).
- **File Storage:** Uploads go to `settings.UPLOAD_DIR`. Filenames are server-generated (`{timestamp}_{uuid4}{ext}`). Format whitelist: JPEG / PNG / WebP / HEIC. No malware scanning is performed.
- **Cache:** v3.1 `price_cache` table holds aggregated pricing estimates keyed by item-identity hash. Holds no eBay user data (regression-tested in `test_pricing_providers.py::test_ebay_parser_drops_seller_pii_for_deletion_exemption`).

### Network Security

- **HTTPS:** Enforced in both dev and prod. The dev certs are generated by `frontend/scripts/generate-certs.js` (see `certs/CERTIFICATE-SETUP.md`). In NAS deployments (`docker-compose.nas.yml`) **Caddy** terminates TLS directly on ports 80/443 and obtains/renews Let's Encrypt certs for public hostnames or uses its internal CA for `*.local` names — no upstream proxy required for the common case. The nginx container was retired in v2.4.
- **CORS:** Configured via `CORS_ORIGINS` (HTTPS-only by default). Set a permissive list during LAN-only use; tighten when exposing externally.
- **Rate Limiting:** Per-route limits enforced in-app via [slowapi](https://github.com/laurentS/slowapi) — auth endpoints, vision, and pricing have stricter caps than CRUD. Defaults are tuned for single-household use; tune in the relevant router decorators if you need different limits. For additional WAF / HSTS / IP-level rate limiting, terminate at the reverse-proxy layer (Caddy supports a `rate_limit` middleware).
- **Daily LLM cost caps:** v3.1 `VISION_DAILY_COST_CAP_USD` and `PRICING_DAILY_COST_CAP_USD` enforce per-(user, day) spend ceilings. Over-cap returns HTTP 402 (gracefully) — no further provider calls are made until the next UTC day rolls. The cap is **best-effort**: a call's cost is only known after the provider responds, so the cap blocks the *next* call once the recorded total crosses it — it cannot pre-empt a call already in flight, and two requests that pass the check concurrently will both run. Usage accounting itself is recorded with an atomic in-DB increment, so concurrent calls cannot lose each other's spend. Treat the cap as a spend signal, not a hard billing limit.

### LLM and third-party secrets (v3.1–v3.2)

WHIS v3.1 introduces optional intelligence features that depend on a third-party LLM provider and (optionally) eBay developer credentials. These add new sensitive secrets and a new data-egress path:

- **`LLM_API_KEY`** — your provider API key (OpenRouter, Venice.ai, Ollama, etc.). Treat as a high-value secret: store in `.env` with `chmod 600`, never commit, rotate on any suspected leak.
- **In-app LLM key (v3.2)** — the admin-only Settings page (`/api/llm-config`) can store a provider API key in the database instead of `.env`. It is encrypted at rest with Fernet, using a key **derived from `SECRET_KEY`** (HKDF-SHA256). Two consequences operators must understand: (1) anyone who obtains `SECRET_KEY` can derive the Fernet key and decrypt the stored provider key — so `SECRET_KEY` is as sensitive as the provider key itself; (2) rotating `SECRET_KEY` makes the stored ciphertext undecryptable — the app logs the failure loudly and falls back to the `.env` value, and you must re-save the key in the Settings UI to re-encrypt it under the new `SECRET_KEY`. The same applies when restoring a backup onto a host with a different `SECRET_KEY`.
- **Operator-configurable `base_url` (v3.2)** — the Settings page also lets an admin change the LLM endpoint at runtime. The admin is trusted in WHIS's single-tenant model, but note this is a data-egress control surface: a misconfigured `base_url` sends item images / metadata to whatever host is entered. `LLM_ALLOW_CLOUD=false` (below) hard-fails any non-private `base_url` as a guard against accidental cloud egress.
- **`LLM_BASE_URL`** — the provider endpoint. Combined with `LLM_API_KEY` to form the OpenAI-compatible client.
- **`LLM_ALLOW_CLOUD`** — privacy kill-switch. When `false`, the app refuses to start if `LLM_BASE_URL` doesn't resolve to localhost or a private IP/container hostname. Set `false` if you only intend to use a local Ollama / LocalAI deployment — eliminates the risk of accidentally pointing at a cloud provider.
- **`EBAY_APP_ID` / `EBAY_CERT_ID`** — eBay developer keys for the Browse API pricing path. Used via OAuth `client_credentials` (server-to-server only — WHIS never acts on behalf of an eBay end user). WHIS holds an exemption from the eBay Marketplace Account Deletion notification system on the basis that we persist no eBay user data; see `docs/EBAY_INTEGRATION.md` and the regression test in `backend/tests/test_pricing_providers.py`.
- **Image data egress:** when `VISION_ENABLED=true`, image bytes are sent to your `LLM_BASE_URL` for identification. Backend logs hash references only (`VISION_LOG_IMAGE_HASHES_ONLY=true` by default). Disable vision or point at a local provider if your threat model precludes outbound image transmission.
- **Pricing query egress:** when `PRICING_ENABLED=true` and `PRICING_PROVIDERS` includes `llm`, item metadata (brand, model, name) is sent to the LLM along with an `openrouter:web_search` tool call. No user-identifying data is sent.

## Known Security Limitations

1. **Local Network**
   - Designed for local network use
   - Remote access requires a VPN or a reverse proxy with operator-provided TLS
   - Built-in protection is limited to per-route rate limits (slowapi); there is no WAF or IP-level abuse protection

2. **Authentication**
   - Two roles only: admin (the first registered user; gates the LLM Settings page) and regular user — no fine-grained role-based access control
   - No OAuth / OIDC / MFA integration
   - No password complexity enforcement
   - No refresh-token flow — sessions hard-expire after `ACCESS_TOKEN_EXPIRE_MINUTES`

3. **Backup Security**
   - Backups are plain zip archives (not encrypted at rest)
   - Manual restore process
   - Local storage only

## Security FAQs

**Q: Is my data stored in the cloud?**
A: No, WHIS stores all data locally on your host.

**Q: Can I access WHIS remotely?**
A: Yes, but only via VPN (e.g., Tailscale) or a reverse proxy (Synology DSM, Caddy, Traefik). The application enforces per-route rate limits (login, registration, vision, pricing) but has no WAF or IP-level abuse protection of its own — put those at the proxy.

**Q: How are passwords stored?**
A: Passwords are hashed with **bcrypt** via passlib. Configure rounds by swapping the passlib `CryptContext` arguments in `backend/app/security.py`.

**Q: Are images stored securely?**
A: Image uploads are validated by Pillow magic-byte inspection (not trusted `Content-Type`), enforced against a size cap and dimension cap, and stored with server-generated filenames. There is no malware scanning — if you accept uploads from untrusted parties, front the service with a scanning proxy.

**Q: What happens if `SECRET_KEY` leaks?**
A: All issued JWTs become forgeable. Rotate immediately (`python -c "import secrets; print(secrets.token_urlsafe(64))"`), update `.env`, and restart the backend. All existing sessions will be invalidated since token signatures no longer verify. If you stored an LLM provider key via the in-app Settings page, that key is encrypted under a `SECRET_KEY`-derived key — a leaked `SECRET_KEY` exposes it too, so rotate the provider key as well. Rotating `SECRET_KEY` also makes the stored LLM ciphertext undecryptable; re-save the key in the Settings UI afterwards to re-encrypt it.
